SQL Lens now refuses, before it runs, a query that uses `SELECT *`, `alias.*`
or `TABLE t` to return every column of a table or view, and tells the assistant
to select only the columns the question needs. This keeps columns a question
never asked for, such as contact details or credentials, out of answers.
`COUNT(*)`, a `*` inside `EXISTS (...)`, a `*` over a common table expression
or subquery that names its own columns, and a `*` over a system catalog are
still allowed. System catalogs include ones that hold credentials, such as
`mysql.user` and `pg_catalog.pg_authid`, which database grants should keep out
of reach, and any of your own tables named with a catalog prefix (`pg_` on
PostgreSQL, `sqlite_` or `pragma_` on SQLite); a `*` over any other function that returns rows is refused,
whatever the function returns. Set
`database.refuse_whole_row_selects = false` to turn the refusal off. Whole rows
reached without a `*`, such as PostgreSQL's `row_to_json(t)`, are not caught.
While the refusal is on, a query SQL Lens cannot parse is refused too, as it
already is while `database.read_only` is true.
The assistant is also instructed to decline requests to export, download or
dump a whole table or the whole database, and to say that a full export has to
come from your application. Questions that list rows, such as "show all
customers", are still answered, with only the columns the question needs.
