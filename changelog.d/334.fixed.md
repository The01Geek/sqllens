A `query_database` call that fails partway through a tool call no longer breaks
its conversation. Before, a call that stopped after the agent saved a tool call
but before it saved the tool's result left that unanswered tool call in the
history, and the model API then rejected every later message in the
conversation with a 400 error. Now the unanswered tool call and anything after
it are removed from the history when the call ends, and a WARNING is logged
naming the conversation and how many messages were removed. The call's own
user message stays, and the call still returns the same error it did before. A
cancelled or timed-out call is still rolled back to the history it started
with. Conversations already broken on a running server are not repaired; a
restart clears them, because conversation history is kept in memory. (#333)
