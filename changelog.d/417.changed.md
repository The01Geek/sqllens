Rule-set row rules now check the types of the two columns each join compares
(`inherit`, `referenced_by` and `owner_via`): both must be integers, both
strings, or, for any other type, exactly the same type. A join pair whose types
differ now stops `sqllens serve` from starting, or refuses requests until it is
fixed, because MySQL would otherwise convert a text key such as `'1abc'` to the
number `1` and match rows the rule should hide. A row rule that nests more than
16 `EXISTS` subqueries or needs more than 64 slots now fails to load with an
error naming the rule and the limit, and a rule-set file nested too deeply to
parse now fails with a rule-set file error instead of a bare `RecursionError`.
Before switching to this release, run `sqllens validate --check-db` with it
against your rule-set file and database, and fix any column types or rules it
reports. (#416)
