While a rule-set file is configured, SQL Lens now logs every refused
request at warning level with the refusal's class and the names (never the
values) of the `_meta` keys it kept, or a note that it discarded an
oversized `_meta`. Every `query_database` request also writes one
`rule-set audit:` line at info level naming its outcome (`served`,
`refused: <class>` or `failed`) and the rule set, account ID and user ID
that passed their checks. The audit line does not depend on
`[agent.audit]`. The per-role rule-sets guide is now the canonical
definition of the version-1 rule-set file and lists the feature's limits.
