Per-role rule sets for MySQL (first part). Set `[rule_sets] file` to a
version-1 rule-set file that lists, for each application role, the tables and
columns it may read. SQL Lens validates the file whenever the configuration
loads and checks, at startup or else on the first request, that every listed table and column exists in the
database. Each `query_database` request must then name a rule set, a bound
account ID and a user ID in its `_meta`; a request that does not is refused
before the assistant runs, and every query is limited to the selected set's
tables and columns. While a rule-set file is configured, the assistant saves
nothing to memory (memory import and the memory admin tools are not affected), a conversation can be continued only under the identity that
started it, and `sqllens verify-memory` is not supported. Row rules are not
supported yet, and a rule set not marked as confirmed against production is
refused. Without `[rule_sets] file`, nothing changes. (#374)
