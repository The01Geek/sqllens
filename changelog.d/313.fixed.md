When a data question can be read more than one way and the readings would count
different records, a different period, or a different measure (for example,
whether partially paid orders count toward revenue), the agent is now instructed
to ask one short clarifying question instead of answering with a reading you
never chose. Until you pick a reading or ask to see several, each follow-up that
depends on the choice is meant to get the question again, with the readings
offered as choices and no numbers built on either reading. The `query_database`
tool description tells your assistant to relay the question to you, or use an
answer you already gave, and call again with the returned conversation ID. A
memory note can mark a known ambiguity or name the meaning to use, and a saved
question-and-SQL pair the agent finds settles it; see
[Managing Memory](docs/external/managing-memory.md#settling-ambiguous-questions).
These are model instructions, not enforced rules. `sqllens verify-memory` golden
questions that leave such a choice open, with nothing that settles it, may now
get a clarifying question and be reported as non-PASS; state the choice in the
golden question. (#298)
