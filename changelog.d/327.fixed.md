With `memory.allow_admin_tools` or `memory.allow_import` on, the memory tools
(`list_memories`, `get_memory`, `delete_memory`, `clear_memories`,
`add_memories`, `export_memories`, `get_memory_stats` and `import_memory`) no
longer freeze the server while they read or clear a large memory store:
`/healthz`, other sessions and running `query_database` calls keep being
answered. Their store reads and deletes now run one at a time on a dedicated
worker thread, so a store call that hangs delays later memory tool calls rather
than the whole server. A `list_memories` call that overlaps an import may fail
more often with its retryable "changed during listing" error; it still never
returns a partial listing. The default configuration is unaffected. (#303)
