`query_database` keeps the results of the agent's schema-introspection queries
(catalog reads such as `information_schema`, `pg_catalog`, `sqlite_master` or
SQLite `pragma_*` functions) out of the answer: they add no table or text
block, while the agent still receives them. Catalog queries are classified with
the configured database's SQL dialect, so a data table that only starts with
another engine's catalog prefix (for example `pg_payments` on MySQL) is shown,
and a MySQL catalog query using `DATABASE()` does not clear an earlier query
error. A data table whose name starts with the configured engine's own catalog
prefix (`pg_` on PostgreSQL, `sqlite_` or `pragma_` on SQLite) counts as a
catalog read and its rows are not shown; rename it, or expose it through a view
with a different name, if you need its rows in answers. (#301)
