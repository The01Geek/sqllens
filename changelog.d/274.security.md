Row-level security no longer lets a database view hide reads of a protected
table. With RLS rules configured, SQL Lens checks every referenced relation on
the connection that runs the query and blocks views, including views over
unprotected tables and PostgreSQL materialized views, as well as SQLite virtual
tables and any relation whose type it cannot verify. A fixed set of
metadata-only system views, such as `information_schema.columns`, stays
readable for schema lookups; value-bearing statistics views such as
`pg_catalog.pg_stats` stay blocked. SQLite RLS now requires SQLite 3.37 or
newer, unquoted non-ASCII PostgreSQL identifiers must be quoted, and custom SQL
runners used beneath RLS must accept the `require_base_tables` keyword. Rules
still match table names only, so PostgreSQL partition or inheritance children
and stored functions that read protected tables need separate handling. See
[Row-Level Security](docs/external/row-level-security.md#limitations). (#261)
