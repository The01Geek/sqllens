SQL Lens now hides the values of secret-looking columns in query results by
default. When a result column's name matches a secret word such as password,
hash, token, PIN, secret or API key, every value in it is replaced with
`[withheld]` before it reaches the result table, the model, the server log or
the result CSV on disk, and the assistant is told which columns were withheld.
Masking judges by the column name alone, so a column renamed by an alias is
still returned as stored; keep column grants on the SQL Lens database user as
the real control. After upgrading, non-secret columns with matching names (for
example `token_count` or `content_hash`) also show `[withheld]`: list them in
the new `[result_masking].unmasked_columns` setting to show them again, and use
`extra_words` to hide more columns. A configuration containing
`[result_masking]` does not load in older releases. See
[Configuration](docs/external/configuration.md#section-result_masking).
