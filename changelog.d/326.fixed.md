`sqllens serve` now stops at startup with exit code 2 when the memory store's
existing `chroma.sqlite3` file cannot be written by the server process, printing
`Preflight failed: memory: memory store file <path> is not writable by this
process: ...`. Chroma cannot open such a store at all, so starting anyway would
answer every question without saved memory. `sqllens validate --check-memory`
runs the same check, but it tests the access of the user running it, so run it
as the server's user. This happens most often in Docker, where the image runs as
the non-root `sqllens` user (uid 1000) and a bind-mounted store was written by a
root container; fix it by giving that user ownership of the store directory, for
example `sudo chown -R 1000:1000 <host directory>`. The check leaves the file
unchanged; see
[Startup preflight](docs/external/configuration.md#startup-preflight-on-sqllens-serve).
