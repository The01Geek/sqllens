PostgreSQL support. SQL Lens now serves MySQL 8.0+ (including Aurora MySQL 3)
only: the PostgreSQL query runner, the `postgres` install extra and libpq in the
Docker image are gone, and `pip install "sqllens[postgres]"` installs no
database driver. A `database.url` whose scheme is not `mysql://` or
`mysql+<driver>://` (SQLite URLs are still accepted until SQLite's own removal)
now fails every `sqllens` command that loads the config, `validate` and `serve`
included, with `unsupported database URL scheme; use a mysql:// or
mysql+pymysql:// URL (MySQL 8.0+)`; that covers `postgresql://`, `mysqlx://`
and a URL with no `://`. Earlier entries in this release that describe
PostgreSQL support or PostgreSQL fixes no longer apply. If you ran SQL Lens
against PostgreSQL, move to a MySQL 8.0+ database. If a config used a
non-MySQL URL only as a stand-in for `sqllens validate` without `--check-db`,
switch it to a MySQL URL such as `mysql+pymysql://user:pw@host:3306/db`: that
run opens no database connection, so the URL need not reach a real server.
