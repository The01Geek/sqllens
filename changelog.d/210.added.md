`sqllens verify-memory PATH [--format json|csv] [--fail-under PCT] [-c CONFIG]`
runs a curated golden file of reference questions through the live assistant
and classifies each one as PASS, CHANGED, or ERROR by comparing the generated
SQL against the expected SQL after dialect-aware normalization. A golden file
uses the same shape as a memory bundle's question-and-answer block, so the
existing bundle limits (10 MiB, 10,000 items) apply. CSV golden values are
preserved without spreadsheet formula-protection prefixes.
Each question is a full live assistant run (typically several billed
language-model requests, plus the queries it runs against your database).
A verification run disables memory saving and retrieval-counter updates,
even if `memory.save_queries` is enabled. The command
exits non-zero on an empty golden file, on any non-PASS case (without
`--fail-under`), and on a run where no case passes (even with
`--fail-under 0`). SQL parse failures on either side produce ERROR details
identifying the failing side. Verification uses the persisted default profile's
retrieval threshold and limits within the configured row and iteration caps,
while forcing SQL details on. See
[Managing memory](docs/external/managing-memory.md#verifying-memory-after-an-import).
