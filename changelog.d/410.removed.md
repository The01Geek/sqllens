SQLite query-engine support and the bundled SQLite demo. SQL Lens now runs
queries only against MySQL 8.0+: a `database.url` whose scheme is `sqlite` or
starts with `sqlite+` is refused at config load, so `sqllens validate` and
`sqllens serve` exit with `unsupported database URL scheme; use a mysql:// or
mysql+pymysql:// URL (MySQL 8.0+)`. Point `database.url` at a MySQL 8.0+ server
with a `mysql://` or `mysql+<driver>://` URL, for example
`mysql+pymysql://user:pw@host:3306/db`. Pipelines that run `sqllens validate`
without `--check-db` on a `sqlite:///…` stand-in should use a MySQL URL instead,
such as `mysql+pymysql://ci@127.0.0.1/ci`, which needs no running server. The
demo is now `examples/mysql-demo`, a Chinook MySQL database started with Docker
Compose, so the demo needs Docker. `SqliteRunner` is no longer exported from
`sqllens.agent.integrations`. Earlier entries in this release that describe
SQLite as a query engine no longer apply. The ChromaDB memory store, including
its `chroma.sqlite3` file, is unaffected.
