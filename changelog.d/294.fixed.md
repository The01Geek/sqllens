A question waiting on the AI service or on your database no longer stops SQL
Lens from serving other requests. The calls that used to hold up the whole
server — the Anthropic request and the database query — now run on worker
threads, so the health check keeps answering (Docker no longer marks a busy
container `unhealthy`) and questions from different conversations are answered
at the same time instead of queueing behind each other. Questions that share a
conversation are still answered one at a time, in arrival order; if a client
cancels a question, the messages that attempt added are removed so the next
question on that conversation continues from the history it started with.
Answers themselves are unchanged. Two scope limits remain: `import_memory` and
the memory-administration tools still run on the server's main loop and can
briefly block other requests, and a cancelled question's database query keeps
running on its worker thread until it finishes or the configured
`statement_timeout_ms` stops it — so server shutdown waits for it, and with
`statement_timeout_ms = 0` nothing but the query's own end stops it. A question
is still answered in a single response, so one slower than your client's own
timeout still times out for that client.
