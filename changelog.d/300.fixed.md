The HTTP server now stays responsive while `query_database` runs are in
progress. Model calls use the asynchronous Anthropic client and SQL queries run
on a dedicated pool of eight worker threads, so they no longer hold the
server's event loop. Before this fix, `/healthz` and quick tools such as
`list_data_sources` could time out during an agent run, and a container health
check could report the server as unhealthy. A query that waits more than a
minute for a free worker now fails with "All database workers are busy; try
again shortly." (#299)
