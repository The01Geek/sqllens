A new `agent.show_conversation_footer` setting (default `true`; environment
override `SQLLENS_AGENT__SHOW_CONVERSATION_FOOTER`) keeps the conversation ID
out of `query_database` text when set to `false`: answers no longer end with the
conversation-ID note, and agent-run error messages no longer end with a
`Conversation ID: <id>` line. The ID is still returned in the
`sqllens/conversation` response metadata, and with the setting off it is also
returned there on every agent-run error, so a
host that reads it can continue the conversation. See the
[Configuration reference](docs/external/configuration.md#section-agent).
