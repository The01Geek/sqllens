Memory groups limit what each per-role rule set reads from memory. A rule set
may list `memory_groups`, and memory bundle items (`sql_pairs` pairs and
`schema_docs`) may carry `groups`. While a rule-set file is configured, a
request reads only untagged memory and memory tagged with one of its set's
groups, both through the assistant's memory search and through the memory added
to its instructions; `sqllens verify-memory --rule-set` reads the same. Existing
memory stays untagged and visible to every set, with no migration. An import
through `sqllens import-memory`, `import_memory` or `add_memories` that names a
group no rule set lists is refused before anything is written or cleared.
JSON exports keep each record's groups; a CSV export of tagged memory is
reported as lossy. `list_memories` and `get_memory` show groups,
`get_memory_stats` adds `unretrievable_count`, and `get_access_rules` lists each
set's `memory_groups`. See [Memory groups](docs/external/rule-sets.md#memory-groups).
