**The assistant no longer saves free-form notes by default** — SQL Lens no longer writes free-form notes of its own about your schema into memory unless the new `memory.save_text_memories` setting is turned on, and it is off by default. **This is a behavior change for existing deployments:** an instance that previously let the assistant build up its own notes stops adding them after this upgrade. To keep the old behavior, set `save_text_memories = true` in the `[memory]` section of your `sqllens.toml`, or set `SQLLENS_MEMORY__SAVE_TEXT_MEMORIES=true`; on an MCPB install, turn on the new "Let the assistant save free-form notes" checkbox in the extension's settings. Free-form notes saved earlier stay in memory and are still used as background context for later questions, and loading curated notes with `sqllens import-memory` is unaffected by this setting. SQL Lens records nothing about where a note came from, so a note the assistant saved cannot be told apart from one added by an import. If earlier notes are wrong, operators who configure SQL Lens with a TOML file or environment variables can review the free-form notes and delete the wrong ones with the memory-administration tools — see [Memory-Administration Tools for the Assistant](docs/external/managing-memory.md#memory-administration-tools-for-the-assistant) for how to enable them and what deleting requires. An MCPB install's settings offer no way to turn those tools on. See [Configuration](docs/external/configuration.md#section-memory). (#267)
